# 插件评审清单

用途：评审别人（或自己）提交的 `plugins/<id>/` 时的依据。每条给**严重度**和**怎么验**。
严重度定义：

- **P0** 会造成实际危害（注入、越权、数据丢失、宿主崩溃、用户机器卡死）→ 必须改，不放行
- **P1** 会在真实使用中出错（泄漏、竞态、静默失败、状态被抹）→ 必须改
- **P2** 质量问题（可读性、重复、口径不一致、体验）→ 本轮或记账
- **Q** 评审者自己的误判风险 → 先取证再提

## 0. 评审纪律（先做这一步）

1. **跑起来看，不要只读代码。** 能断言的写成断言：`npm run verify:<id>` 是否真存在、真过、真还原状态。
2. **每条问题要能复现**：给文件:行号 + 触发步骤 + 期望/实际。给不出的，降级为疑问句提出。
3. **数错方向前先找参照系**。历史上两次评审误判都是「看着像 bug、其实无可观察差异」：
   - `Window::emit` 被指「跨窗总线不通」→ Tauri 2 它本来就走 `manager().emit` 广播全部 webview，
     待办插件的桌面卡片就是运行时证据。
   - 状态机 `request()` 里 includes 与优先级判断的先后 → 会打断的请求根本不进队列，没有可观察差异。
4. 结论要落到「改 / 不改 + 为什么」，不要停在「建议考虑」。

## 1. 安全（P0）

| 检查项 | 怎么验 |
|---|---|
| 外部数据没有进 `innerHTML` / `insertAdjacentHTML` / `<template>` 拼接 | `grep -n "innerHTML\|insertAdjacent" plugins/<id>/`，逐处看数据来源；BLE 名、HTTP 响应、总线 payload 都算不可信 |
| 外部值没有拼进 CSS 选择器或 `querySelector` | `grep -n "querySelector(\`\|style.setProperty(\${" plugins/<id>/`；我们真炸过一次：把 `]` 放错位置导致整段表达式解析失败 |
| 没有 `eval` / `new Function` / 动态 `import(变量)` | `grep -n "eval(\|new Function\|import(" plugins/<id>/` |
| 没有绕过 `ctx` 直接调宿主命令 | `grep -n "__TAURI\|invoke(" plugins/<id>/`（插件里出现即为 P0，同 realm 能绕是已知边界，不是可以主动用的理由） |
| `permissions` 与实际用量一致 | 逐项对照：声明了没用的要删，用了没声明的跑一次激活看是否被拒 |
| 凭据/令牌没有落盘成明文可读路径或写进日志 | 看 `ctx.storage.set` 的值与 `ctx.log` 的参数；token 只能进插件隔离存储，且请求头里带上就行 |
| 出网域名最小化 | 每个 `http` 域名都要有理由；不要为了「以后可能用」预先声明 |

## 2. 生命周期与资源（P1）

| 检查项 | 怎么验 |
|---|---|
| `deactivate()` 清掉了自己所有 `setInterval`/`setTimeout` | 读 deactivate；再跑 verify 断言「停用后 N 秒内没有新的出网/回调」 |
| widget 清理表按挂载实例存（`WeakMap(root)`），不是模块级数组 | 三区同时挂载 → 卸载其中一个 → 另两个仍能收到推送（`com.pet.astock/widget.js` 的 `scopes` 是参照实现） |
| overlay 显隐排成串行链，`deactivate` 先等在飞的再 `destroy` | 触发一次 `show` 立刻停用，看卡是否留在屏幕上（`verify:astock` 的「停用后卡收掉」） |
| 同一插件的并发触发不会叠加请求 | 找 busy/串行标志；把网络人为变慢看是否排队 |
| 撤销授权后能重新弹同意框、存储目录被清 | 设置页点「撤销授权」→ 再操作一次 → 应重新弹框且数据为空 |
| 定时器不受隐身/可见性影响而失控 | 不要用 rAF 计时；游戏模式隐藏期间插件仍在跑，确认不会累积 |

## 3. 状态与数据（P1）

| 检查项 | 怎么验 |
|---|---|
| 设置页回显当前配置，不渲染模板默认值 | 改配置 → 关设置窗 → 重开 → 控件值应与存储一致；再「只改一项」看另一项是否被抹回默认（`verify:astock` 有这条） |
| 回显有防冲写守卫：推送不覆盖正在输入的文本/刚选的项 | 在输入框里敲一半、或改 `<select>` 后先不应用，再触发一次状态推送：控件值必须不被冲回旧值（`verify:astock` / `verify:goat-gauge` 的「改了未应用 → 推送不冲掉」组；契约见 PLUGIN_SDK「6.1 设置页回显与防冲写」，实现按插件各一份 `views/settings/lock.js`，源码级共享，复制须带来源注释） |
| 落盘前校验读取值（类型/范围/长度） | 手写坏数据进 `store.json`（错类型、超长字符串、缺字段），重启插件应回落默认而不是崩 |
| 存储 key 数量与结构稳定，升级有迁移或明确丢弃 | 用旧版本 store.json 跑新版本 |
| 原子写、损坏不静默清空 | 宿主 `store_*` 已保证；插件自己写文件是不允许的（P0） |
| 无进展/无数据时的降级显示 | 停牌、断网、接口改版：应显示错误行，不是 NaN、空白或崩 |

## 4. 出网节制（P1，有网络就要看）

| 检查项 | 怎么验 |
|---|---|
| 所有出网收在一个函数里，没有旁路 | `grep -n "ctx.http.request" plugins/<id>/` 应只出现在那个口子 |
| 有最小间隔 + 滚动窗口上限 | 读实现；跑 verify 用耗时证明串行生效（面板三条请求 ≥ 2×minGap） |
| 传输层失败重试一次；429/403 或连续失败进**指数/阶梯冷却** | 冷却期主轮询必须跳过，不能继续撞 |
| 无变化时退避，不 7×24 空转 | 找「数据没前进就拉长间隔」的逻辑，且有上限 |
| 节拍有抖动 | 看是否固定等间隔 |
| 节流/冷却状态对用户可见 | 界面要能解释「为什么这几分钟没更新」 |
| 批量接口优先，用一次请求带走多条 | 数一下 N 条数据是 1 次还是 N 次请求 |

## 5. 验证与文档（P1）

| 检查项 | 怎么验 |
|---|---|
| 有 `tests/e2e/verify-<id>.mjs` 且 `package.json` 挂了脚本 | 实跑；看退出码与末尾汇总 |
| 断言是**真机可观察**的，不是「没报错就算过」 | 画布类要 `getImageData` 数像素；DOM 类要查 closed shadow 里的节点；网络类要断言解析后的值 |
| 断言不依赖运行时刻 | 盘前/收盘/周末都要能跑；用「有价才比大小」这类形式 |
| 纯函数有独立单测 | 列序、边界、脏值、空数据 |
| verify 跑完还原现场 | 撤销授权、插件下线、`host:enabled-plugins` 复原、临时文件删除、自起进程关停 |
| 涉及新脚本/图片/协议源 → 跑过 `npm run verify:release` | dev 不注入 CSP，测不出来 |
| 约定/能力有变动时同步了文档 | `PLUGIN_SDK.md` 能力表、`../../AGENTS.md` 约定、`dist/*/更新说明.txt` |

## 6. 代码质量（P2）

- 注释只写「为什么」，不复述代码在干什么；魔数旁边要有出处（实测日期/对照源）。
- 不引入超出任务需要的抽象与「将来可能用到」的分支。
- 错误处理只在系统边界；内部调用不叠三层 try/catch。
- 命名与现有插件一致（`index.js` 主逻辑、`widget.js` 渲染、`topics.js` 常量）。
- 不留 `console.log`（用 `ctx.log`）。

## 7. 评审输出格式

```
## <插件 id> 评审（<日期>）
结论：放行 / 改后放行 / 打回

P0（必须改，阻断）
1. <文件:行号> 现象 —— 复现步骤 —— 期望
P1（必须改）
...
P2（记账）
...
疑问（取证不足，不作为问题）
...
已核不成立（附证据）
...
```

「已核不成立」这一节必须写 —— 下一轮评审者（或下一批助手）不该再提同一件。
